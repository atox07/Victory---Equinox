# VIctory Equinox

**Experimental mid-range NVIDIA compatibility layer | 0.1.0-equinox.1 (first tester candidate)**

Equinox continues the unfinished VIctory Mid-Range integration of Neptune HyperEngine, Vice-Tay and Neptune FPS. The target is a balanced CPU/GPU/memory configuration rather than a high-end-only profile. It is an independent community fork; not an official PC port and not affiliated with any hardware or software vendor.

**Status:** source candidate, not a validated gameplay release. The finishing pass did not run a Windows Rust build or a real GPU test. No FPS, RAM ceiling, graphics correctness or playability is guaranteed. Earlier upstream measurements are not Equinox results.

No proprietary title executables, assets, extracted shader caches, BCPack tables or keys are supplied. Only use software and interoperability data you are authorized to use. See [asset policy](docs/asset-policy.md) and [credits](docs/CREDITS.md).

## Target hardware (not certified)

- Windows x64 with current graphics drivers and Direct3D 12 support; Windows 11 preferred. Windows 10 support is inherited but unverified.
- Primary target: RTX 4060 8 GB, Ryzen 5 5500, 16 GB RAM, PCIe 3.0 x8.
- Secondary test targets: RTX 2060/3060/5060/5070, Ryzen 3600/5600/5700/5800X, 16–32 GB RAM. GPU feature support and driver behavior must be verified individually.
- Development builds require the pinned Rust MSVC toolchain, Visual Studio C++ Build Tools and Windows SDK. Testers using the compiled package do not need Rust or Visual Studio.

## Build from GitHub (manual only)

1. Extract the source ZIP, open the `VIctory-Equinox` folder and upload **its contents**, including `.github`, `.cargo` and `.victory-root`, to your repository root. Preserve the license and credits. Do not upload any personal runtime data.
2. Open **Actions → Equinox / Windows x64 tester ZIP → Run workflow**. No push, pull-request or scheduled trigger is configured.
3. Wait for all build/test/package steps to pass. Download the `VIctory-Equinox-Windows-x64` artifact; extract GitHub's outer artifact ZIP, then the inner tester ZIP into a separate directory. The matching `VIctory-Equinox-Source` artifact is supplied for source distribution.
4. If a step fails, retain the full build log and report the first actual error. Do not treat an unsuccessful workflow as a playable build.

The workflow builds release and instrumented executables, checks the package, and verifies a synthetic launcher round trip on Windows. It needs no proprietary test input. It fetches the pinned Direct3D Agility SDK redistributable from NuGet and verifies its SHA-512 digest. Cargo dependencies are resolved using the supplied lockfile.

## Local development build

From a Windows developer PowerShell:

```powershell
cargo check --locked --workspace --all-features --all-targets --target x86_64-pc-windows-msvc
cargo test --locked --release --workspace --target x86_64-pc-windows-msvc
cargo build --release --locked -p victory --target x86_64-pc-windows-msvc
cargo build --profile diag --locked -p victory --features diagnostics --target x86_64-pc-windows-msvc
```

The executables are under `target/x86_64-pc-windows-msvc/release` and `target/x86_64-pc-windows-msvc/diag`. For a complete tester package, run the manual workflow or `tools/Package.ps1` with the two executable paths and an output directory outside the source checkout. The package contains the pinned redistributable and licensing notices.

## Tester quick start

Keep the extracted tester directory intact. The compatibility layer uses authorized local test inputs only; none are included. `Launch.ps1` is the supported entry point. Inspect scripts before running them and follow your local PowerShell policy.

```powershell
.\Launch.ps1 -ShowSettings
```

Supply the local authorized test executable through `-Title` when performing an interoperability test. The launcher supports paths containing spaces. `-ShowSettings` works without launching a title. If the authorized test needs BCPack, provide the lawfully available external file through `-BcpackTables`; it is not bundled or generated by the project. Missing tables can prevent decoding. The launcher performs a size check and the decoder validates the table structure.

### Profiles

| Setting | BASELINE | MID-RANGE (default) |
| --- | --- | --- |
| Purpose | Approximation of HyperEngine settings on the integrated runtime | Conservative mid-range test candidate |
| Console model | Series S | Series S |
| Window | Fullscreen | 1920x1080 |
| Pool sizing | Fixed | RAM tiers and adaptive VRAM budget |
| Copy-back | Smart copy-back enabled | Full copy-back path; Smart filter disabled |
| Indirect records | CPU-validated raw mode 3 | Checked mode 0 |
| Texture view / rectangle / legacy FP32 corrections | Off | On |
| In-place memory | Off | Auto; only sufficiently fast detected NVIDIA links |
| Ocean readback | On | On |
| Ray tracing | Off | Off |

BASELINE is a settings comparison on the same Equinox binary, **not** a bit-identical upstream build. For a true upstream A/B use the original build separately. For safe comparisons of physics use `-Disable SmartCopyBack` for BASELINE as well, noting the override in the report.

The MID-RANGE launcher selects 16 or 32 GiB RAM tiers and sizes worker groups based on logical CPU count. Auto in-place stays off on unknown links and nominal PCIe 3.0 x8. It does not promise a hard memory ceiling. Upload gap coalescing is opt-in (`-UploadGapKiB`), not a default. Frame generation is not added by Equinox. The built-in upscaler is distinct from frame generation; record its mode and keep it fixed in comparisons.

Other useful controls are `-Ram 16`, `-Window 1920x1080`, `-InPlace Off`, `-WarmMode Auto`, `-Diagnostics`, and `-GpuTiming`. Use `Get-Help .\Launch.ps1` or inspect its parameter list for all supported switches. Do not mix legacy launchers with the new profiles. Old upstream scripts are retained for attribution and comparison only.

## Diagnostics and privacy

The launcher writes local sessions, data and cache outside the checkout, under `%LOCALAPPDATA%\VIctory-Equinox`. It prints the session path. On a normal return it calls `Diagnose.ps1`; if interrupted, run diagnostics against the session folder manually. Raw logs remain local. Review the sanitized ZIP before sharing; it includes hardware configuration, numeric measurements and error counters, not raw logs, dumps, caches or title paths.

```powershell
.\Diagnose.ps1 -Session 'C:\Path To Local Session' -StartSecond 60 -DurationSeconds 120
```

See [benchmark protocol](docs/BENCHMARK.md), [integration notes](docs/INTEGRATION.md), and [changelog](CHANGELOG.md). A successful Present interval is not proof of a unique fully rendered image. The runtime has not yet been validated at 15, 20 or 30 FPS on the target PC.
